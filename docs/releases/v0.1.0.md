The first release of Dustbunny: it finds the appdata folders that stay behind when you delete a Docker stack,
tells you why each one is orphaned and how much space it takes – and only reads, never deletes.

## Highlights

- **Finds orphaned folders** in your scan roots (e.g. `/opt/appdata`) by checking every folder against
  - running and stopped containers (bind mounts, named volumes bound to a host folder, compose labels),
  - Portainer stacks, including stopped ones whose containers are gone,
  - compose folders for Dockge, Komodo or plain `docker compose`.
- **Explains every folder:** active, stopped, defined only, orphaned or ignored – with the containers and
  stacks that use it.
- **Size, last change and "orphaned for 23 days"**, remembered across restarts.
- **Safe when in doubt:** mounts of the whole scan root (backup tools) don't hide orphaned folders, unknown
  `${VARIABLES}` still protect matching folders, and incomplete or uncertain results never notify.
- **Notifications** through Apprise (ntfy, Discord, e-mail, Telegram, …) when folders become orphaned or are
  no longer orphaned.
- **Web UI** for phone and desktop: English and German, four skins (Dark, AMOLED, Light, Mango), your own
  skins in `/data/skins`, ignore a folder with one click, optional password.
- **Read-only by design:** read-only mounts, a socket proxy that only allows reading, a read-only container
  file system, no capabilities except reading.

## Install

Use [`docker-compose.yml`](https://github.com/Jake-double-one/dustbunny/blob/main/docker-compose.yml) as a
Portainer stack or with `docker compose up -d`. **Mount your appdata under the same path as on the host**
(`/opt/appdata:/opt/appdata:ro`) – see the README for why.

## Not in this release

Quarantine and deleting orphaned folders are planned as an opt-in feature. This version only reads.
